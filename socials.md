## LinkedIn

My 16GB MacBook Air couldn't handle multiple Claude Code sessions—VS Code kept crashing. I upgraded to 48GB, which solved the crashes, but I still had no visibility into which session was eating memory.

Activity Monitor shows 47 node processes. Not helpful when you need to know: Which Claude session is the hog? Can I spawn another subagent? Which Chrome tabs should I close first?

So I built RAMBar—my first macOS app, built entirely with Claude Code.

It sits in your menu bar and shows RAM the way developers think about it:
- Claude Code sessions (expandable to see main vs subagent)
- Chrome tabs by memory (expandable)
- VS Code workspaces, Python, Docker, and more

Now I know at a glance whether I have headroom for more subagents, or if I need to close some Chrome tabs first.
